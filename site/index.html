Stronghold Crusader, rewritten in C++ one function at a time.

OpenSHC is the community's rewrite of the 2002 castle game. A function counts as done only when Microsoft Visual C++ 2005 compiles the new source to the same machine code as the game's own executable, checked instruction by instruction. Every finished function already runs in the game: OpenSHC's DLL hooks it in place of the original.

    How a function gets to 100%

    Matching decompilation, the method behind the decomps of Super Mario 64, Ocarina of Time and LEGO Island.

    1. 01

      Find it

      Take one function at its address in the 1.41 executable and study it: what calls it, what it calls, which structures it reads and writes.

      Ghidra
    2. 02

      Write it

      Write C++ that a person can read and change, with named types and fields, following the project's style guide.

      C++clang-format
    3. 03

      Compile it

      Build it with the compiler whose output matches the original's: Microsoft Visual C++ 2005, Service Pack 1.

      MSVC 8.0 SP1CMake
    4. 04

      Compare it

      reccmp, from the LEGO Island decompilation, lines the new function up against the original instruction by instruction and scores the match.

      reccmp
    5. 05

      Land it

      At 100% the function is merged into main, and OpenSHC's DLL runs it in the game in place of the original.

      OpenSHC.dll

    The last few percent

    A function at 95% usually does the right thing already. What's left is the compiler's choices: a value kept in ebx where the original kept it in esi, two statements in the other order, a signed compare that should be unsigned, a loop the optimiser shaped differently.

    Closing that gap means finding the source the original programmers must have written, which is why one function can take an afternoon.

        Where the numbers come from

        Only OpenSHC's public data: status_rollup.tsv from its latest-sarif release, which lists every function with its best match on main or on the branches the project tracks, and main's status/addresses-SHC-3BB0A8C1.txt with its git history. Forks the rollup doesn't track can hold more finished work than this page shows.

        A GitHub Actions workflow rebuilds the page every day at 05:17 UTC. The raw numbers are yours too: progress.json, functions.json.
